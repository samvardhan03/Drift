# Drift

**Regime-aware factor research platform for equities.**

Drift is a systematic alpha research stack that layers five analytical engines — factor scoring, regime detection, IC-weighted signal combination, portfolio optimisation, and risk decomposition — on top of NSE universe data. This repository is a **public demonstration shell**: the API routes and dashboard are fully functional, but all analytic responses are served from precomputed fixtures generated on synthetic data. The proprietary inference engine is not included.

> **Demo build notice:** Every response from this API is a precomputed fixture generated by running the production engine on seeded geometric-Brownian OHLCV data (not real market prices). Ticker names are real NSE symbols; every numeric value is synthetic. Do not use for investment decisions.

---

## What this demonstrates

| Layer | Description | Route |
|---|---|---|
| Factor Screener | Rank the Nifty 50 universe by momentum, quality, value, beta, and size scores | `GET /screen` |
| Signal Computation | Per-ticker factor scores and regime-conditional composite signal | `POST /signals/compute` |
| Portfolio Optimisation | HRP, Black-Litterman, CVaR weight allocation | `POST /portfolio/optimise` |
| Portfolio Analysis | Full factor/risk/regime diagnostic for an existing portfolio | `POST /portfolio/analyze` |
| Risk Decomposition | BARRA-style factor vs specific variance attribution | `POST /risk/decompose` |
| Stress Testing | Historical scenario P&L (COVID crash, taper tantrum, Fed hike cycle) | `POST /risk/stress` |
| Backtest | Walk-forward equity curve, drawdown, Sharpe, PSR/DSR | `POST /backtest/run` |
| Dashboard | Streamlit UI — signal explorer, portfolio weights, risk attribution, backtest | `streamlit run src/dashboard/app.py` |

## Architecture

```
src/
  api/
    main.py               FastAPI app — 6 demo routers, no auth
    models.py             Pydantic request/response contracts
    screener_models.py    Screener-specific models
    deps.py               Dependency injection (returns mock services)
    routers/
      screener.py   signals.py   portfolio.py
      risk.py       backtest.py  analyze.py
  showcase/
    services.py     MockScreener, MockSignals, MockBacktest, …
    provider.py     SyntheticProvider (bundled parquet loader)
    fixtures/       JSON fixtures — validated through pydantic at boot
  dashboard/
    app.py          Streamlit four-page dashboard
    demo.py         Fixture loader for the dashboard
  data/
    universes.py    Nifty 50 / Nifty 100 / Bank Nifty ticker lists
data/
  synthetic/
    ohlcv_demo.parquet   50 tickers x 756 business days, seed 42
```

The dependency-injection seam is `deps.py`. Setting `DRIFT_MODE=showcase` (the default) makes every route use `src/showcase/services.py`. Each mock service loads its fixture JSON at import time and validates it through the same pydantic response model the router declares — a fixture that drifts from the contract raises `ValidationError` at startup, not silently at runtime.

## Quickstart

```bash
git clone https://github.com/samvardhan03/Drift.git
cd Drift
pip install -e .

# Start the API
uvicorn src.api.main:app --reload

# In a separate terminal — start the dashboard
streamlit run src/dashboard/app.py
```

The API will be available at `http://localhost:8000`. Interactive docs at `http://localhost:8000/docs`.

## Docker

```bash
docker build -t drift-showcase .
docker run -p 8000:8000 drift-showcase
```

## Example requests

```bash
# Screen Nifty 50
curl http://localhost:8000/screen

# Compute signals for a subset
curl -X POST http://localhost:8000/signals/compute \
  -H "Content-Type: application/json" \
  -d '{"tickers": ["TCS", "INFY", "HDFCBANK", "ICICIBANK", "RELIANCE"]}'

# Portfolio optimisation
curl -X POST http://localhost:8000/portfolio/optimise \
  -H "Content-Type: application/json" \
  -d '{"tickers": ["TCS", "INFY", "HDFCBANK", "ICICIBANK", "RELIANCE"], "method": "hrp"}'

# Risk decomposition
curl -X POST http://localhost:8000/risk/decompose \
  -H "Content-Type: application/json" \
  -d '{"weights": {"TCS": 0.3, "INFY": 0.3, "HDFCBANK": 0.4}}'

# Backtest
curl -X POST http://localhost:8000/backtest/run \
  -H "Content-Type: application/json" \
  -d '{"tickers": ["TCS", "INFY", "HDFCBANK", "RELIANCE", "ICICIBANK"]}'
```

## What is and is not included

The protected core — the elements that constitute the production inference engine — are **not present in this repository in any form**:

- Gaussian HMM regime detector (state labeling, filtered-probability logic)
- Wavelet scattering feature construction (Cauchy bank parameters, stability scores)
- Factor library (rank-transform pipeline, factor definitions)
- IC/ICIR estimator and regime-conditional signal combiner
- Portfolio optimisers (Black-Litterman view construction, HRP, CVaR)
- Ledoit-Wolf covariance estimator and BARRA factor risk model
- Backtest engine (walk-forward, transaction cost model)
- Broker integration (Kite Connect, TOTP, token management)
- Billing and authentication

The disclosure boundary: literature-level formulas (Cauchy scattering, IC/ICIR, Black-Litterman posterior) are referenced in the production documentation but not implemented here. What is protected is the specific implementation — calibration choices, NaN handling, regime/omega machinery, and the signal-combination logic.

## Development

pip install -e ".[dev]"
